--------------------------------------------------------------------------------
1. WHAT THIS PROJECT IS
--------------------------------------------------------------------------------
This repo ("ebicsa") is built on the ICS "nextjs-application-template" - a
Next.js 16 sample app that doubles as a starter kit. It is a CRUD app for a
"Stuff" entity (name, quantity, condition, owner) with full auth, roles,
and admin features already wired up.

IMPORTANT: As of this writing, the codebase is essentially the STOCK
TEMPLATE. Git history shows only two commits ("Initial commit", "Replaced
old issues template") and there is NO ebicsa-specific code yet - no matches
for "ebicsa" anywhere in the repo. Everything below describes what the
template gives you, not what has been customized.

--------------------------------------------------------------------------------
2. WHAT IS ALREADY IMPLEMENTED (per index.md + code inspection)
--------------------------------------------------------------------------------
Tech stack:
  - Next.js 16.1.6 (App Router, Turbopack) + React 19 + TypeScript
  - Bootstrap 5 via react-bootstrap; theme via CSS vars in globals.css
  - React Hook Form + Yup for forms
  - NextAuth v5 (beta) for auth; bcrypt-hashed passwords
  - Prisma 7 + PostgreSQL (@prisma/adapter-pg)
  - SweetAlert2 for success/failure alerts
  - Playwright for e2e tests; ESLint for lint; GitHub Actions CI

Pages (src/app):
  - /                     Landing page (currently just "Welcome to this
                          template" - NOT yet customized for ebicsa)
  - /auth/signin          Sign in
  - /auth/signup          Register
  - /auth/signout         Sign out
  - /auth/change-password Change password
  - /list                 List your own Stuff items (edit links per row)
  - /add                  Add a Stuff item
  - /edit/[id]            Edit a Stuff item
  - /admin                Admin page: lists ALL users' Stuff (admin only)
  - /not-authorized       Shown when a non-admin hits a protected route
  - not-found.tsx         404 page

Backend / data:
  - prisma/schema.prisma: User (id, email, password, role[USER|ADMIN]) and
    Stuff (id, name, quantity, condition[excellent|good|fair|poor], owner).
    NOTE: owner is stored as an email STRING, not a relation to User.
  - prisma/migrations + src/seed.ts; seed data comes from
    config/settings.development.json
  - src/lib/: auth.ts, authOptions.ts, dbActions.ts, page-protection.ts,
    prisma.ts, validationSchemas.ts

Auth/authorization behavior:
  - Any registered user can add/list/edit stuff; each user only SEES their
    own stuff on /list, but per the docs any logged-in user can edit any
    item (ownership is not enforced on edit).
  - Role ADMIN (set in settings file) unlocks /admin; non-admins hitting it
    get redirected to /not-authorized even via direct URL.
  - Route protection lives in src/lib/page-protection.ts.

Tests: tests/admin-pages.spec.ts, tests/john-pages.spec.ts, tests/auth-utils.ts

Steps to implement:
  1. Prereqs: PostgreSQL running, `cp sample.env .env` with a valid
     DATABASE_URL, then `npx prisma migrate dev`, `npx prisma generate`,
     `npm run seed`, `npm run dev` -> http://localhost:3000
  2. Open each doc/*.png next to its page.tsx and restyle/restructure the
     JSX to match. Use react-bootstrap components (Container, Row, Col,
     Card, Form, Button, Table, Navbar) - do NOT hand-roll CSS unless the
     mockup demands it. Shared chrome (nav/footer) lives in
     src/components/Navbar.tsx and Footer.tsx - change it once, everywhere.
  3. Keep existing data wiring: pages call functions in src/lib/dbActions.ts
     and forms use React Hook Form + the Yup schemas in
     src/lib/validationSchemas.ts. If the mockup needs new fields, update
     prisma/schema.prisma -> `npx prisma migrate dev` -> update seed +
     validationSchemas + form components.
  4. Preserve route protection (src/lib/page-protection.ts) and the
     /not-authorized flow for admin pages.
  5. Verify per page: `npm run lint`, then visually in `npm run dev`.
     Before committing, run `npx playwright test` (tests may need updating
     if you change labels/routes the specs depend on - see
     tests/auth-utils.ts).

5. COMMENTS / GOTCHAS WORTH REMEMBERING
--------------------------------------------------------------------------------
  - TEMPLATE BASELINE: when in doubt whether something is intentional,
    diff against https://github.com/ics-software-engineering/nextjs-application-template
  - Stuff.owner is an email string, NOT a foreign key - filtering "my
    stuff" compares owner to session email. Renaming users breaks this.
  - Edit permission is NOT owner-restricted (any logged-in user can edit
    any item). If ebicsa needs ownership enforcement, that's new work.
  - settings.development.json defines admin@foo.com / john@foo.com, both
    password "changeme". settings.production.json is gitignored - use it
    for deploys.
  - The seed only runs via `npm run seed`; schema changes need migrate +
    generate before the app/typecheck will pass.
  - next-auth is v5 BETA - APIs differ from v4; auth code is split across
    src/lib/auth.ts and authOptions.ts.
  - Duplicate next.config.mjs / next.config.ts - consolidate to one.
  - checklists/ folder has per-topic review checklists (ui, react, ts,
    architecture, testing, design) - good pre-commit self-review.
  - index.md doubles as the project website source (_config.yml present);
    keep it in sync with real behavior.
  - doc/ images are the ONLY spec for the mockups - there is no Figma/
    design file in the repo. If a mockup is ambiguous, ask before guessing.
